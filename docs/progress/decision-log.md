# Decision Log

> **Last updated:** 2026-08-28

Small calls that affect other people but do not warrant a full ADR. One line each. Newest at the top.

**Write an entry when:** you rename something shared, change a shared file, choose between two equally reasonable implementations, or discover something that changes how someone else should work.

**Write an [ADR](../decisions/) instead when:** the decision shapes the architecture, adds a dependency, or someone will later ask "why is it like this?"

| Date | Decision | Made by | Affects |
|---|---|---|---|
| 2026-08-29 | **Never use `timestamp` for a column recording when something HAPPENED — use `dateTime`.** MySQL and MariaDB give the FIRST `timestamp` column in a table an implicit `DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` unless `explicit_defaults_for_timestamp` is on, which it is not in XAMPP. Three columns were being silently rewritten by any UPDATE that did not name them: `tickets.opened_at` (**destroying the SLA baseline on every status transition** — confirmed live, 00:52:02 became 01:04:58 from a status change alone), `telemetry_hourly.hour_bucket` (the 1062 duplicate-key error in the log), and `telemetry_readings.recorded_at` (armed, no damage yet). `created_at`/`updated_at` stay as `timestamp` — being touched automatically is their job. | Bugfix | Everyone |
| 2026-08-29 | **`php artisan atlas:check-schema` audits the live database for traps the suite cannot see.** Read-only, so it is safe to point at real data — a test using `RefreshDatabase` against MariaDB would wipe it. **Run it after any migration and before a submission.** Three defects have now shipped through a fully green suite purely because tests run on SQLite and the system runs on MariaDB: MySQL-only `FIELD()`, MySQL-only `DATE_FORMAT`, and the auto-updating timestamps above. | Bugfix | Everyone |
| 2026-08-28 | **An unknown `ATLAS_TELEMETRY_DRIVER` throws; it does not fall back to the simulator.** A typo in `.env` silently producing invented data on a system meant to be showing real readings is the worst outcome available. `SnmpTelemetrySource::collect()` throws for the same reason — an empty collection would look like forty access points going quiet at once. | M5 | Everyone |
| 2026-08-28 | **`layouts/app.blade.php` gained `@stack('scripts')`, and its position is load-bearing.** `@vite` emits `type="module"`, which is deferred and runs after parsing — so a plain `<script>` pushed to the stack defines its `x-data` function *before* `Alpine.start()`. Push a module, or defer it, and Alpine initialises first, cannot find the function, and the element renders as blank markup with nothing in the console. | M5 | Everyone |
| 2026-08-28 | **The simulator gives each access point a fixed personality derived from its id.** Without it the same AP is not consistently the busy one, "which access point is the problem?" has no stable answer between runs, and M7's risk ranking ranks noise. ADR-0002 warns that uncorrelated telemetry leaves the predictive module with nothing to find; there are tests asserting both the daily curve and the latency/saturation correlation. | M5 | M7 |
| 2026-08-28 | **Aggregated latency excludes offline readings.** An unreachable access point has no latency, so counting it as zero makes an outage read as the best hour that AP ever had. Uptime is carried as its own column instead — which is also the figure the report quotes. | M5 | M7 |
| 2026-08-28 | **Date truncation is written per driver.** `DATE_FORMAT` is MySQL's and `strftime` is SQLite's; the suite runs on SQLite and MariaDB ships, so anything vendor-specific passes review and fails the moment a test touches aggregation. Same class of trap as `FIELD()` in M4. | M5 | Everyone |
| 2026-08-28 | **`DemoDataSeeder` now creates one account per role**, from `ATLAS_DEMO_PASSWORD` and the `ATLAS_DEMO_*` keys in `.env`. Most built screens belong to the assistant and engineer, so a fresh install with only the administrator could not open the inspection form or the ticket queue at all. All three are tagged `is_demo` so `atlas:purge-demo-data` removes them; with `ATLAS_DEMO_MODE=false` they are never created. Re-running the seeder **resets** a forgotten password rather than failing — that is the supported recovery path, not editing the database. | Demo setup | Everyone |
| 2026-08-28 | **Q3 adopted rather than ratified.** M4 could not be built without a lifecycle, and the team has not met on it, so the proposal in `docs/04-open-questions.md` was implemented exactly as written — including "Reporter or engineer" for closing, and keeping the SLA. **This is still cheap to overturn:** the machine is one array in `TicketService::TRANSITIONS` and the targets are three lines in `config/atlas.php`. Anyone who wants a different lifecycle should say so rather than assume it is now fixed. | M4 | M4, M6, M7 |
| 2026-08-28 | **The ticket state machine lives in `TicketService` and nowhere else.** `status` is absent from `Ticket::$fillable`; buttons render from `nextStates()` so the UI cannot offer an illegal move; and `transition()` throws for anything the map forbids, so a hand-written POST is refused too. Hiding a button is a suggestion, not a rule. | M4 | Everyone |
| 2026-08-28 | **Comment visibility is a query scope, never a Blade condition.** `TicketComment::scopeVisibleTo()` is the only place it is decided. A view that filters is one misplaced `@if` from leaking internal notes to the person who reported the fault, and the mistake is invisible in review because the data is in the variable either way. Any future "some rows are hidden from some people" needs the same treatment. | M4 | Everyone |
| 2026-08-28 | **No `FIELD()` or other vendor-specific SQL in `orderByRaw`.** The engineer queue sorts by priority with a portable `CASE`, because the test suite runs on SQLite while MariaDB is what ships — `FIELD()` passes review and fails the moment a test touches the query. | M4 | Everyone |
| 2026-08-28 | **Route grouping follows the Policy, not the role.** Ticket transitions and comments sit outside the role-guarded groups: closing and reopening belong to the reporter, so an assistant behind `role:engineer` could never reach the route that lets them say "this was not actually fixed". Role middleware is for whole areas; per-record permission is a Policy's job. | M4 | Everyone |
| 2026-08-28 | The overall-result enum is **`InspectionOutcome`**, renamed from `InspectionResult`. The old name collided with the Eloquent model for the `inspection_results` table, and PHP refuses two imports sharing a short name — every M3 file needs both, so one would have been aliased in all of them. The distinction reads correctly anyway: the enum is the outcome of the whole inspection, the model is one row of results. | M3 | Everyone |
| 2026-08-28 | **`ChecklistCategory` added** (boot/display/peripheral/network). `checklist_items.category` is a bare string in the ERD; ADR-0004 says every such column gets a backed enum, and it is the only way the inspection form's section headings get real labels and a defined order — the order somebody actually checks a machine in. | M3 | M3, M7 |
| 2026-08-28 | **Checklist items are edited as part of their template, not through their own controller.** Position in the submitted list IS `sort_order`, so saving one item alone would have nothing to say about where it sits. `Admin\ChecklistItemController` named in the module spec was therefore not built. | M3 | M3 |
| 2026-08-28 | **Reordering is up/down buttons, not drag-and-drop.** A drag library is a new dependency needing an ADR, and HTML5 drag-and-drop does not work by touch — the checklist builder would be the one screen a tablet could not operate. Any future reorderable list should copy this rather than reach for a library. | M3 | Everyone |
| 2026-08-28 | **`inspections.shift_id` has no foreign key yet.** The column is there because the ERD has it, but `shifts` does not exist — M6's migration adds `->foreign('shift_id')`. Nothing writes it until then. Any module needing a column on a table another module has not built yet should do the same rather than inventing the table. | M3 | M6 |
| 2026-08-28 | **`having()` against a `withCount` alias is invalid SQL.** `withCount` adds a correlated subquery column, not an aggregate, so HAVING needs a GROUP BY and SQLite rejects it outright. Use `whereHas()` to filter and `withCount()` to display. This 500'd the assistant's landing page and no test caught it, because no test rendered it. | M3 | Everyone |
| 2026-08-28 | **Read a Collection with `->get($key)`, never `$collection[$key]`.** Array access throws on a missing key, so the inspection form 500'd for every inspection that had no saved answers yet — which is every inspection at the moment it starts. Every test of that route asserted a 403, so none of them ever rendered it. **A route whose tests only assert failures has never been rendered.** | M3 | Everyone |
| 2026-08-28 | `<x-form.select>` gained a **`blank`** prop, alongside `placeholder`. `placeholder` renders a *disabled* first option, which is right for a form ("Choose a location") and wrong for a filter bar — once a filter was set, the option that clears it was greyed out and there was no way back to "any". `blank` renders a selectable empty option. Use `placeholder` on forms, `blank` on filters; never both. | M2 | Everyone |
| 2026-08-28 | **Retiring a lab PC writes two columns together** — `status = retired` and the soft-delete stamp — and `restore()` reverses both. `retired` is excluded from the form dropdown and rejected by `LabPcRequest`, because it is what the Retire button does, not a value you pick. One column without the other gives a machine that is retired in a report and operational in every list on screen. Access points have no equivalent case: `ApStatus::Maintenance` means "temporarily off", not "gone", so AP removal is the soft delete alone. | M2 | M3, M5, M7 |
| 2026-08-28 | Resource routes for `lab-pcs` and `aps` carry **`->withTrashed(['show'])`**. Without it the model binding 404s on exactly the records retirement was meant to preserve, and "keeps its history reachable" is false. Any module adding a show page for a soft-deleted model needs the same. | M2 | Everyone |
| 2026-08-28 | Counting a location's assets before deleting it uses **`withTrashed()`**. The soft-delete scope hides a retired PC from the relation, so a plain count reports the location empty and the delete then fails at the foreign key — handing the user the raw error the check exists to prevent. Any "is this still referenced?" count on a soft-deleting model has the same trap. | M2 | Everyone |
| 2026-08-28 | **`DB_CONNECTION=mariadb`**, not `mysql`. XAMPP ships MariaDB 10.4.32 and Laravel 12 has a dedicated driver (`MariaDbConnector`). Deferred since Stage 1; settled before the first migration because MariaDB implements `JSON` as `LONGTEXT` with a check constraint rather than a native type, which changes how M7's `risk_assessments.factors` behaves. Verified with `php artisan db:show`. | Stage 4 | Everyone, M7 |
| 2026-08-28 | The first administrator's credentials come from **`.env`** (`ATLAS_ADMIN_EMAIL`, `ATLAS_ADMIN_PASSWORD`), never from a committed file. A default password in the repository is a credential shared with six people. The seeded account is flagged `must_change_password`. | Stage 4 | Everyone |
| 2026-08-28 | `role`, `is_active` and `is_demo` are **deliberately not in `User::$fillable`**. Privilege must never be assignable from request input — a mass-assigned `role` turns any profile form into privilege escalation. M1's admin controller sets them explicitly through a Policy. Same rule for `risk_score` / `risk_band` / `is_demo` on `LabPc` and `AccessPoint`: written by the system, never by a form. | Stage 4 | M1, M2, M7 |
| 2026-08-28 | **One form vocabulary: `<x-form.*>` everywhere.** Breeze's `x-text-input` / `x-input-label` / `x-input-error` / `x-primary-button` are deleted. Breeze's error component had no `aria-describedby`, `aria-invalid` or `id` linking it to its input, hardcoded indigo instead of the brand token, and used `border-gray-300` against our `border-slate-300`. A test asserts none of them ever return. | Stage 1–3 audit | Everyone |
| 2026-08-28 | Form components take a **`bag`** prop for named error bags. Two forms on one page — the profile screen is the existing case — validate into separate bags, and a field reading the default bag renders **no error at all**, silently. `<x-form.input name="password" bag="updatePassword" />`. | Stage 1–3 audit | Everyone |
| 2026-08-28 | **Never nest a Blade comment inside a Blade comment.** The inner closing token ends the outer one, and everything after it becomes live template code. A usage example inside a component docblock then gets compiled and evaluated — `<x-risk-gauge :score="$assessment->score" />` in a comment threw "Attempt to read property on null" from a file that looked inert. Keep examples in plain indented text. | Stage 3c | Everyone |
